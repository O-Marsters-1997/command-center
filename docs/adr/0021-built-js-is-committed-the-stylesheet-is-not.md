# 21. Built JS is committed, the stylesheet is not

**Date:** 2026-10-11 · **Status:** accepted

## Context

The keyboard model (`docs/plans/keyboard-and-search.md`) needs one script that presses whatever
carries a `data-key`. It was first specified as hand-written JavaScript so that keys work with no Node
step, which put untyped, untestable logic (platform detection, chord timing, field guards) in the one
file every page loads, outside Biome, `tsc` and `bun test`.

`app.css` was committed (ADR 1) and the island JS was gitignored. `app.css` is derived from the
templates plus `web/app.css`, so it changes with every template edit and is the recurring conflict in
stacked PRs. The JS changes only when `web/src` does, and keys are core navigation: a Go-only checkout
without them is a regression, not a fallback.

## Decision

- The dispatcher is `web/src/keys.ts`, strict TypeScript, with pure logic (key to binding, chord state
  machine, target resolution) separate from the DOM listener and unit-tested like `layout.ts`.
- Vite builds `keys.js`, `graph.js`, `launch-modal.js` and their shared chunk to
  `internal/web/assets/dist` with hash-free names, and all of it is committed. A Go-only checkout has
  working keys and islands. CI's `assets` job runs `git diff --exit-code internal/web/assets/dist` after
  a build, so stale JS fails CI.
- `app.css` is generated by `just assets` and gitignored. `just build`, `just run` and `just demo` depend
  on `assets`. Go tests that read the sheet skip when it is absent.
- `data-key` stays the only contract between Go templates and the script (one binding per element,
  `mod+` for the platform modifier, a space for a chord).

## Consequences

Changing `web/src` needs `just assets` and a committed rebuild. Template edits no longer touch a
committed file. A binary built with plain `go build` and no `just assets` serves a 404 for
`/assets/app.css` and renders unstyled; the cost is accepted. The CI `assets` job no longer guards the
stylesheet's `@source` scan, since the sheet is untracked. Single-character shortcuts still owe WCAG
2.1.4 a way to switch them off; that is a separate decision.
