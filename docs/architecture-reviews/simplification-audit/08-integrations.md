# 08 Integrations audit (git, gh, runner, agentlog, auth)

## 1. Essential core
- git: every exported func in git.go/checkout.go has a loop/app/demo caller (verified by grep): worktree map incl. mid-rebase handling, MergesCleanly (--write-tree), MidMerge/MergeAbort, RemovalStateFor, EnsureCheckout+NormaliseRemote, tp New/Remove. Genuinely needed, git semantics are the product. ~400 of 660 prod lines are essential.
- gh: List (bulk + per-branch fallback), the 8 verb methods (all called from loop), decode/normalise of the statusCheckRollup union. Essential. gh.Forge and git.Worktrees interfaces each have 2 impls (CLI + demo sim), so they are legitimate seams, not YAGNI.
- runner: Spawn (setpgid, argv substitution, strip API key), Liveness via ps, Cancel (SIGTERM->SIGKILL on pgid), Reap. Essential. Runner interface has real + Fake, Fake used by 9 loop test files: keep.
- agentlog: Parse/ParseLine (log view), ParseMetrics (persisted per-request usage, context curve), ParseReadings (rate-limit gauges), ParseTranscriptUsage/LoadRequests/Weight (spend fit). All have consumers.
- auth: only GeneratePassword + HashPassword have prod callers (cmd/cc/subcmd_prod.go:93-134), and they feed a password nobody checks (see finding 1).

## 3. Comment violations summary
Comment lines (prod / test): git 112/25, gh 50/4, runner 60/38, agentlog 64/22, auth 9/0 = 295 prod, 89 test. By comments.md I estimate ~100 prod lines pass (exported contracts <=3 lines, Darwin zombie EPERM, gh rollup union, merge-tree exit status, squash-merge rationale). ~150-190 prod lines fail: unexported-function narratives, issue/section citations used as justification ("(issue #91)" x8), 10+ line doc comments, `ponytail`-style apologies. Test comments: ~25 fail. Exported funcs with no doc (git.Add/Commit/StagedPaths) are fine under the rule only if contract is non-obvious; no add needed.
Note: git.go MergesCleanly doc (14 lines) and Spawn doc (10 lines) breach the 3-line hard cap.
